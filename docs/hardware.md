# 硬件：引脚分配与接线

本文件是**引脚这件事的唯一说明处**。代码里凡是引用引脚的宏
（`KEY1_Pin` / `OLED_SCL_GPIO_Port` …）都由 CubeMX 从 `.ioc` 生成，
改接线要改 `.ioc`（走 [`cube-recipes/`](../cube-recipes/)），不要改代码。

## 主控与时钟

| 项 | 值 | 说明 |
|---|---|---|
| MCU | STM32F407VET6 | LQFP100，512 KB Flash，128 KB RAM + 64 KB CCMRAM |
| 封装 | LQFP100 | CubeMX 里 `Mcu.Package=LQFP100` |
| HSE | 8 MHz 晶振 | 接 **PH0 = OSC_IN / PH1 = OSC_OUT** |
| 主频 | 168 MHz | PLLM=8 / PLLN=336 / PLLP=2 / PLLQ=7，AHB /1、APB1 /4、APB2 /2 |
| APB1 | 42 MHz | 定时器时钟 84 MHz |
| APB2 | 84 MHz | 定时器时钟 168 MHz；**ADC 时钟源 PCLK2 = 84 MHz** |
| FLASH 等待周期 | 5 | 168 MHz 下必须 ≥5，CubeMX 已按主频算好 |
| 调试 | SWD | **PA13 = SWDIO / PA14 = SWCLK**，用物理引脚而不是 `SYS.Debug` 那个键 |

| 引脚 | 信号 | 方向/模式 | 接什么 | 代码里的宏 | 谁配的 |
|---|---|---|---|---|---|
| PH0 | RCC_OSC_IN | 外部晶振 | 8 MHz 晶振 | — | CubeMX |
| PH1 | RCC_OSC_OUT | 外部晶振 | 8 MHz 晶振 | — | CubeMX |
| PA13 | SYS_JTMS-SWDIO | 复用 | ST-Link SWDIO | — | CubeMX |
| PA14 | SYS_JTCK-SWCLK | 复用 | ST-Link SWCLK | — | CubeMX |

| **PB6** | GPIO_Output | **开漏** + 上拉 + 高速 | OLED **SCL** | `OLED_SCL_Pin` / `OLED_SCL_GPIO_Port` | CubeMX，驱动会再配一遍 |
| **PB7** | GPIO_Output | **开漏** + 上拉 + 高速 | OLED **SDA** | `OLED_SDA_Pin` / `OLED_SDA_GPIO_Port` | 同上 |
| **PA0** | ADC1_IN0 | **模拟输入** | NTC 模块 **AO** | — （ADC 通道不用宏） | CubeMX |

| **PA8** | TIM1_CH1 | **AF 开漏** + 无上下拉 | 风扇 **PWM 线** | `FAN_PWM_Pin` / `FAN_PWM_GPIO_Port` | CubeMX |
| **PA1** | TIM2_CH2 | **AF 输入** + 上拉 | 风扇 **FG 线** | `FAN_TACH_Pin` / `FAN_TACH_GPIO_Port` | CubeMX |
| **PB0** | GPIO_Output | 推挽，**初始低** | 继电器模块 **IN** | `RELAY_IN_Pin` / `RELAY_IN_GPIO_Port` | CubeMX |
| **PB1** | GPIO_Output | 推挽，**初始高** | 有源蜂鸣器 **IO** | `BUZZER_IO_Pin` / `BUZZER_IO_GPIO_Port` | CubeMX |
| **PC7** | GPIO_EXTI7 | **上拉输入** + 中断，**双边沿触发** | 红外接收头 VS1838B 的 **OUT** | `IR_RX_Pin` / `IR_RX_GPIO_Port` | CubeMX |

> `PA0` 在 CubeMX 里被规范化成 `PA0-WKUP`（它带唤醒功能），这是同一个引脚。

CubeMX 对 **ADC 通道不生成引脚宏**（不像 GPIO 会生成 `KEY1_Pin` 那样），
所以 `ADC_CHANNEL_0` 与 PA0 的对应关系只写在
[`bsp/bsp_adc.h`](../bsp/bsp_adc.h) 的注释里——那正是 BSP 层的职责：
「这块板子上，什么接在什么脚上」。

## 接线

### 调试串口（USART1 ↔ CH340）

```
CH340 TX  ──►  PA10 (MCU RX)
CH340 RX  ◄──  PA9  (MCU TX)
CH340 GND ───  GND
```

**TX/RX 必须交叉，且必须共地**。不共地时常见现象是「能发不能收」或 `err` 计数持续上涨。

### OLED（SSD1306，四针模块）

```
模块丝印      接到
---------     --------------------------------
GND      ──   GND
VCC      ──   3V3      （不要接 5V，理由见下）
SCL      ──   PB6
SDA      ──   PB7
```

四针模块的丝印顺序各家不同，**接线前按丝印核对，不要按位置猜**。
模块板载 4.7 kΩ 上拉已在 SCL/SDA 上，无需外接。

### NTC 测温（LM393 型四针模块）

```
模块丝印      接到
---------     --------------------------------
VCC      ──   3V3      ⚠️ 必须 3.3V
GND      ──   GND
DO       ──   （不用；那是 LM393 比较器的数字输出）
AO       ──   PA0
```

模块上 AO 取的是**固定电阻与 NTC 串联分压的中点**：

```
   3V3 ──[ R_FIXED ]──┬── AO ──► PA0
                      │
                  [ R_NTC ]
                      │
                     GND
```

温度升高 → `R_NTC` 变小 → AO 电压下降。实测确认了这个方向
（捏住热敏电阻时 `raw` 从 2105 掉到 1733）。

### 按键（两个轻触开关）

```
K1:  PC0 ──┬── 开关 ── GND        K2:  PC1 ──┬── 开关 ── GND
           │                                 │
        （芯片内部上拉）                  （芯片内部上拉）
```

另一端接 GND，引脚配上拉输入，所以**按下读到低电平**。
若实际接法相反（另一端接 VCC），要同时改两处：
`bsp/bsp_key.c` 里的 `BSP_KEY_ACTIVE_LEVEL` 和 `.ioc` 里这两个引脚的上下拉。

### 风扇（12V 4 线 PWM）

```
   风扇线        接到
   ---------     ------------------------------------
   GND     ──   板子 GND ／ 12V 电源负极   ⚠️ 必须共地
   +12V    ──   12V 电源正极
   PWM     ──   PA8     （TIM1_CH1，25 kHz，开漏）
   FG      ──   PA1     （TIM2_CH2 输入捕获，内部上拉）

   12V 电源负极 ──── 板子 GND      ⚠️ 这根线不能省
```

**上电顺序固定：先让板子跑起来，再给风扇 12V。** 反过来的话，PA8 还是复位后的
浮空输入，风扇的 PWM 引脚被它自己的内部上拉顶到高电平 —— **风扇立刻全速转**，
而且看起来像「PWM 完全不起作用」。

**为什么 PWM 用开漏，而不是推挽。** 4 线风扇的 PWM 脚内部自带上拉
（Intel 4-Wire PWM 规范：拉到 3.3V 或 5V，开路电压上限 5.25V），主板侧只负责
拉低。用开漏驱动，高电平由风扇自己建立，不管它上拉到 3.3V 还是 5V 都不会和
MCU 的输出级对顶。PA8 在数据手册里是 `I/O FT`（5V 耐受），5.25V 也在范围内。

> 佐证这条规范的一个现象：**PWM 线悬空时风扇全速转**——那正是被内部上拉拉高了。

**为什么是 25 kHz。** Intel 规范给的是 21~28 kHz、标称 25 kHz。TIM1 挂 APB2，
APB2 分频 = 2 → PCLK2 = 84 MHz → 定时器时钟 = 2×84 = **168 MHz**，
`PSC = 0`、`ARR = 6719` → 168e6 / 6720 = 25.0 kHz。

**FG（测速）。** 开集输出，**每转 2 个脉冲**（Intel 规范），正常风扇自己**不带**
上拉，要靠主板拉。本工程用 STM32 内部上拉（约 40 kΩ）兜底，没接外部电阻。
⚠️ 少数风扇的 FG 内部上拉到 5V/12V —— **那种直连会打坏 PA1**，接线前务必用
万用表量一下 FG 对 GND 的电压（安全值：约 0V 或 3.3V 级）。

> 内部 40 kΩ 偏弱，长线上容易有振铃导致边沿被重复捕获（转速读数偏大）。
> 若与风扇铭牌对不上，在 PA1 与 3V3 之间加一只 4.7 kΩ，并开 TIM2 的输入滤波器。

**⚠️ 低于 20% 的占空比行为未定义。** 规范写明 20% 以下由厂商自定；本工程实测
0% 时风扇维持约 295 rpm 而非停转。要真正停转只能切 12V。

**⚠️ 线色不可信。** 本项目实际撞过一次：按常规配色接的 PWM/FG 两根线是反的，
现象就是「占空比怎么调都没反应 + `fg` 恒为 0」。判定方法（不用万用表）：
保持 12V 供电，把疑似 PWM 的线从板子上拔掉 —— 风扇**立刻回到全速**就是 PWM 线，
毫无变化就是测速线。

### 继电器模块（高电平触发）

```
   模块丝印      接到
   ---------     ------------------------------------
   VCC      ──   独立 5V 电源正极     ⚠️ 不要接板子的 3.3V
   GND      ──   板子 GND            ⚠️ 必须共地，否则 PB0 的电平没有参考点
   IN       ──   PB0                 （高电平吸合、低电平断开）
   COM      ──   12V 电源正极
   NO       ──   小灯模块正极         （小灯负极回 12V 电源 GND）
```

`IN` 接的是模块板载三极管/光耦的输入，属高阻；真正吃电流的线圈由模块自己用
VCC 驱动，所以 MCU 侧只是给一个电平、不是给功率。

**线圈走独立 5V 是有意的**：那 70~90 mA 若压在板子 3.3V 轨上，会和 OLED、
蜂鸣器抢余量。实测旁证：继电器吸合期间串口 `drop` / `err`
全程为 0、板子连续运行约 148 秒无复位。

### 有源蜂鸣器模块（低电平触发）

```
   模块丝印      接到
   ---------     ------------------------------------
   VCC      ──   3V3（板子）
   GND      ──   GND
   IO       ──   PB1                 （低电平响、高电平静音）
```

「有源」= 内部自带振荡电路，**给电就响**，MCU 只需给电平，不能用 PWM 去调音调
（无源蜂鸣器正相反）。引脚在 CubeMX 里的初始电平必须是**高**：低电平触发若不
显式设初值，默认的低电平会让它在开机到应用层接管之间「叫一嗓子」。

### 红外接收头（VS1838B，三针）

```
   模块丝印       接到
   ---------     ------------------------------------
   OUT      ──   PC7                 （双边沿中断，内部上拉）
   GND      ──   GND
   VCC      ──   3V3                 （支持 2.7~5.5V，接 3.3V 与 MCU 同电平）
```

⚠ **引脚顺序按丝印核对，别按位置猜。** 这一颗常见封装是「镜头朝自己、
左→右 = OUT / GND / VCC」，但仿制品确实有排法不同的，而且**没有防反接**——
接错位置等于把 VCC 灌进 OUT。三根线用万用表对一下就行：
GND 与板子地是通的。

**输出是什么信号。** VS1838B 是「解调式」接收头：内部已完成 38 kHz
解调、放大与整形，OUT 给出的是**空闲高、收到载波时拉低**的数字电平
（不是原始红外波形）。NEC 的位宽、引导码都在这个包络上量出来，
所以 MCU 侧只需要一个能记时的边沿中断，不需要 ADC、也不需要做软件解调。

**为什么是 EXTI 而不是定时器输入捕获。** 解码需要**双边沿**（载波突发的起止各一个沿），
而 CubeMX 的 TIM IP 定义里，输入捕获的极性只开放上升/下降两档，
BOTHEDGE 那一项是被注释掉的（详见
[`cube-recipes/r5-ir-receiver.txt`](../cube-recipes/r5-ir-receiver.txt) 顶部）。
两次边沿的中断入口延迟是一样的，时长**之差**照样准，所以 EXTI 完全够用。

**上拉。** 模块多半板载一只（常见 10 kΩ）；没有的话靠 PC7 的内部上拉
（约 40 kΩ）也能工作，但边沿会变缓，信号质量要求高时补一只 10 kΩ。

**中断优先级取 4**：串口 2 > FG 捕获 3 > 红外 4 > SysTick 15。
红外排最后是有意的——丢一个沿只是少一帧，按住不放时下一帧（约 110 ms）
就能补上，而串口的接收寄存器只有 1 字节深。

## 为什么 NTC 模块必须是 3.3V

两条独立的理由，任何一条都足以否决 5V：

**① 量程会被削顶。** ADC 的参考电压 `VREF+` 是 3.3V。模块若用 5V 供电，
AO 输出 0~5V，高过 3.3V 的部分**全部被压平在满量程 4095**——
温度偏低的那一大段读数完全一样，等于那段没有区分度。

**② 过压。** 数据手册的引脚表里 PA0 标着 FT（5V 耐受），但那条脚注写的是
「FT = 5 V tolerant **except when in analog mode**」。
PA0 一旦被配成 ADC 的模拟输入**就不再是 5V 耐受**，输入上限是 VDDA（绝对最大 3.6V）。
5V 会经保护二极管倒灌。

3.3V 还带来一个附带好处：模块 VCC 与 ADC 的 `VREF+` 取自同一条轨，
换算 NTC 阻值时**两者相消**（推导见
[`module/temperature/temperature.h`](../module/temperature/temperature.h)），
于是 3.3V 轨实际是 3.26V 还是 3.34V 都不影响结果。

## ADC 采样时间为什么取 480 周期

NTC 分压的中点，源阻抗是 `R_FIXED ∥ R_NTC`：常温下约 5 kΩ，
温度很低（NTC 阻值变大）时逼近 10 kΩ。这属于「高阻信号源」，采样时间必须给够。

数据手册的 ADC 特性里给了约束：

```
RAIN  <  k / ( fADC · CADC · ln(2^(N+2)) )  −  RADC
```

取 `k = 480`（周期数）、`fADC = 21 MHz`（见下）、`N = 12`，
算出来的上限在几百 kΩ 量级，本例的 10 kΩ 远远够用。
**480 是 F4 允许的最长档**，取它对高阻源最宽容，代价只是单次转换约 23 µs——
本工程一秒才采一次，可以忽略。

### 但 ADC 时钟必须先降下来

`k` 里的 `fADC` 由 `ClockPrescaler` 决定。F4 的 ADC 挂在 **PCLK2 = 84 MHz** 上，
而 CubeMX 的默认档是 `/2` = **42 MHz**，超过 F407 ADC 的 **36 MHz** 上限。

所以配方里显式写了 `ADC_CLOCK_SYNC_PCLK_DIV4` → 21 MHz。
依据：CubeMX 的 ADC IP 定义
`db/mcu/IP/ADC-aditf2_v1_1_Cube_Modes.xml` 里 `FadcConstraint` 的
`Max = 36000000`，且 `/2` 那一档自带
`Diagnostic="Prescaler divider not respecting Fadc Min Max Constraint"`。

⚠️ 这个参数**不会出现在 `.ioc` 里**（它等于 CubeMX 按本芯片约束解析出的默认值），
所以只能去生成的 `MX_ADC1_Init()` 里确认 `hadc1.Init.ClockPrescaler`。
详见 [`walkthrough.md`](walkthrough.md) 阶段 12.3。

## 软件 I2C 的电气前提

I2C 要求**任何一方只能把线拉低，不能主动拉高**，所以 SCL/SDA 必须是开漏输出，
高电平靠上拉电阻。本板的上拉来源有两处：

| 来源 | 阻值 | 作用 |
|---|---|---|
| OLED 模块板载 | 4.7 kΩ | **主要上拉**，实际决定上升沿 |
| STM32F4 内部上拉 | ~40 kΩ | 仅兜底：模块没插时总线不浮空，ACK 检测结果是稳定的「无应答」而不是随机值 |

> F4 的输出模式下内部上拉是**真的生效**的（F4 有独立的 PUPDR 寄存器）。
> 这一点和 STM32F1 相反——F1 的输出模式没有内部上拉，HAL 会静默忽略 `Pull` 字段。
> 所以从 F1 项目抄过来的注释里「内部上拉无效」那句话，在 F4 上**是错的**。

另外，RM0090 §8.3.10 写明：GPIO 配成输出时，施密特触发器仍然使能、
IDR 每个 AHB1 周期采样引脚电平。**位翻转 I2C 因此可以直接读回总线真实电平**
（`HAL_GPIO_ReadPin` 读的是 IDR），不必在输入/输出模式之间来回切换。
ACK 检测正是靠这一点。

## 生成物与手写代码的边界

| 路径 | 谁管 | 手写代码能否放 |
|---|---|---|
| `Core/`、`Drivers/`、`cmake/stm32cubemx/`、`startup_*.s`、`*.ld` | CubeMX | **只能放 `/* USER CODE BEGIN */ ~ END */` 内** |
| `CMakeLists.txt`（顶层）、`cmake/` 下的构建脚本（`*.cmake` 工具链文件与 `cmake/stm32cubemx/CMakeLists.txt`） | 只生成一次，之后不重写 | 可以放心手写 |
| `app/` `bsp/` `driver/` `interface/` `module/` `docs/` `tools/` | 你 | 随便写 |
